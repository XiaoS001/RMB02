# 运维手册 · RMB02

> 本地开发 / Docker / CI 三套环境。

---

## 一、本地开发

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python app.py              # 默认 5102 端口
```

- 打开 http://127.0.0.1:5102
- 演示账号：eval/eval123456 · annotator/annot123456 · client/client123456

## 二、测试

```bash
python -m pytest tests -q    # 165 passed
```

🔴 测试用内存库（conftest 注入 `sqlite:///:memory:`），**绝不碰 data/rmb02.db**。

## 三、Docker

```bash
docker compose up -d
# 或
docker build -t rmb02 . && docker run -p 5102:5102 -v rmb02-data:/app/data rmb02
```

### 容器内约束

- **非 root**：`appuser`（uid=1001）运行，数据目录需可写（CI 冒烟验过）
- **单 worker**：SQLite 多 worker 会 `database is locked`，`GUNICORN_WORKERS` 默认 1
- **健康检查**：`/healthz`（只读配置快照，不触发业务逻辑）
- **可执行位**：entrypoint.sh 在 Dockerfile 里 `chmod +x`（Windows git 不保存可执行位）

## 四、CI（GitHub Actions）

`.github/workflows/ci.yml` 三个 job：

| job | 做什么 |
|---|---|
| `test` | pytest 165 条 + 语法编译检查 + 密钥扫描 + 业务库不污染 |
| `docker-build` | 构建镜像（buildx + GHA cache） |
| `smoke-run` | 容器真跑起来：`/healthz` 200 · 非 root（appuser）· 容器内能写库 · 页面 200 · 未登录 401 |

## 五、故障排查

| 现象 | 排查 |
|---|---|
| 端口被占 | 改 `RMB02_PORT` |
| SQLite locked | 确认单 worker（`GUNICORN_WORKERS=1`） |
| 页面 500 | 确认 templates/ 存在（4 个页面）；`python app.py` 看日志 |
| 评分全 parse_failed | 确认模型返回 4 维 JSON（含 hallucination）；否则本地规则降级 |
