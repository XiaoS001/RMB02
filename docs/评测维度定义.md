# 评测维度定义 · RMB02

> 阶段 3 产出 · 2026-10-18
> 四个维度，每维 0~100，加权总分。**所有比例必带 n。**

---

## 一、四个维度

| 维度 | 英文键 | 含义 | 权重 | 为什么这么定 |
|---|---|---|---|---|
| **准确性** | `accuracy` | 与参考答案的一致性 | **0.4** | 评测平台的核心价值是"答得对不对"。它是唯一有客观参照（参考答案）的维度，权重最高 |
| **相关性** | `relevance` | 答案是否切题（没跑题、没说废话） | **0.3** | 答非所问是仅次于答错的失败；且不依赖参考答案，能独立判断 |
| **格式合规** | `format` | 结构是否符合要求（JSON/列表等） | **0.2** | 机器消费的关键：格式错 = 无法用。但格式错不等于内容错，权重适中 |
| **幻觉检测** | `hallucination` | 答案里的引用是否都在证据里 | **0.1** | 只适用于**有证据来源**的输出；权重最低是因为它只在有证据场景才有意义 |

> 🔴 **幻觉维度只适用于「有依据来源」的输出**（任务单 v2 第五节第 7 条）：
> 无证据的开放式生成，此维标 **N/A**（`hallucination=None`），**不计入总分**。
> 不许强打 0 分或 100 分 —— 那等于对"本来就没有依据可查"的答案乱判。

---

## 二、总分计算

```
有证据:  total = accuracy*0.4 + relevance*0.3 + format*0.2 + hallucination*0.1
无证据:  total = (accuracy*0.4 + relevance*0.3 + format*0.2) / 0.9   ← 归一，幻觉维不计
```

**无证据为什么要归一**：如果不归一，无证据输出总分天然比有证据低 10%，
两类输出无法横向比较。归一后同一把尺子量。

---

## 三、各维度打分规则（本地兜底）

| 维度 | 规则 |
|---|---|
| accuracy | 参考文本在输出里 → 100；否则按字面重叠比例 ×100 |
| relevance | 空 → 0；<5 字 → 20；<20 字 → 60；其余 → 90（长度代理信号，真实模型评测用参考答案/人工标注） |
| format | 期望 JSON → 能 parse 100 否则 0；期望 list → `-`/`[` 开头 100 否则 50；无期望 → 非空 100 |
| hallucination | 有证据时：答案里 `[N]`/`[doc:N]` 必须在证据集里 → 100；无引用或引用越界 → 0/30 |

---

## 四、🔴 打分格式漂移兜底（复验意见风险 1）

模型输出结构化分数时**必然有格式漂移**（这是模型的本性）：

| 漂移形态 | 示例 |
|---|---|
| markdown 代码块 | ` ```json {"accuracy":85,...} ``` ` |
| 中文前缀 | `分数如下：{"accuracy":85,...}` |
| 分数带单位 | `"accuracy": "85分"` |
| 缺维度 | `{"accuracy":85}`（少了 relevance） |

**兜底规则**（`scorer.parse_model_score`）：
- 剥代码块 → 剥中文前缀/后缀 → 解析 JSON
- 解析失败 / 缺维度 / 类型错 / 超出 0~100 → 返回
  `{"ok": false, "reason": "score_parse_failed", "raw": "..."}`
- 🔴 **绝不静默当 0 分** —— 0 分会污染统计（一条 parse failed 的样本
  会拉低整体均值，看起来"模型答得差"其实是"分数没解析出来"）

---

## 五、稳定性实测（复验意见风险 3 / 4）

- **n = 5 条样本 × 3 遍 = 15 次调用**（写死，不许少）
- 每条样本报**分数波动区间**（不是只有整体均值）
- 报**极差**（max - min）
- 波动大（极差 > 30）如实说"这个维度不稳定"，不许挑好看均值
- 🔴 `run_index` 必须是**独立的三次完整评测**：`Score` 表里同一
  `model_output_id` 真有 3 条不同 `run_index` 的记录（不许一次评测塞 3 个样本冒充）

### ⚠️ 当前实施状态（审查意见 2026-10-18 15:40 钉死）

> 🔴 **`stability.py` 的 `_model_score_for` 是本地模拟**（`accuracy = 80 + run_index*2`），
> 所以本阶段报出的"波动区间 85.5~87.1、极差 1.6"**来自模拟波动，不是真实模型的稳定性**。
> 真实稳定性需要接真模型跑 3 遍才能测。
>
> **这个 1.6 不许写进简历/项目介绍当作"模型输出稳定"的证据。**
